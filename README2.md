### 1.4 初赛创新

- **整体设计：**

	在 2025 年 ARDB 命令行原型的基础上，2026 年明确了项目的**插件化和实用化**定位。

	一方面，将异步调试能力封装为完整的 VS Code 调试器扩展，提供图形化的异步执行逻辑调用树面板，使开发者在交互式调试中直观理解异步执行关系；另一方面，将 OS 跨特权级调试能力整合进该平台，致力于实现四种调试场景（普通程序、异步程序、操作系统、异步操作系统）的统一配置与无缝切换。四年工作围绕同一技术主线逐步深入，从源代码级 OS 调试到异步程序混合跟踪，再到统一调试平台的工程化集成，形成了覆盖 Rust 系统软件主要调试需求的完整工具链，插件化调试器的工程化跨越。

	【该项目方法的核心洞察是：解释 Rust 异步执行，仅恢复源码层面的等待语义（await edge）不够，必须同时恢复机器级真实控制流（call edge），且需要以 (poll_symbol, env_ptr) 作为实例键区分共享同名 poll 入口的多个 Future 实例。与现有依赖 runtime 主动暴露任务元数据或要求编译期插桩的方案不同，本文方法只依赖二进制与调试器可见信息，不修改被调试源码，天然适用于自定义执行器、无外部 runtime 及底层软件场景。】（不确定是否要加）

- **Async Inspector 图形化面板：**

	设计并实现了 VS Code Webview 面板作为异步调试的可视化前端。面板以多根节点树形图展示异步执行的逻辑调用关系，通过颜色区分 async 协程与 sync 同步函数，节点旁标注 CID、Poll Count、State 等异步元数据，使开发者能从「当前物理调用栈是什么」的传统调试视角，切换到「当前谁在等待谁、这次执行经过了哪条路径」的异步语义视角。白名单生成、编辑、Trace 启动的全流程均集成在面板中，一键完成从代码扫描到异步追踪的完整工作流。

- **工业级 OS 首次适配：**

	完成osgdb调试器（原code-debug）对 StarryOS（组件化 Rust 操作系统）的完整适配，这是该调试器首次对工业级 OS 而非教学 OS 进行的系统性适配。适配过程中解决了组件化架构引入的多项新问题，包括：外部 crate 中的特权级切换点无本地源码、用户程序为动态加载的外部 ELF 二进制、Rust String 类型在 GDB MI 协议中的跨版本读取等。
